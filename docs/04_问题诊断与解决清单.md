# 问题诊断与解决清单

## 1. 安装与编译

### 1.1 Git 克隆超时或 GnuTLS 错误

症状：`curl 28`、`GnuTLS recv error (-110)`、`expected flush after ref listing`。

处理：

```bash
git -c http.version=HTTP/1.1 clone --depth 1 --single-branch --branch <branch> <url> <new-dir>
```

使用新目录，避免旧半成品污染。

### 1.2 找不到 Sophus 或 `sophus/so3.hpp`

根因分两层：系统未安装 Sophus；即使 `find_package` 成功，`lio_node` 也未链接 `Sophus::Sophus`。

处理：把 Sophus 安装到 `~/fastlio2_ws/local/sophus`，构建时传 `Sophus_DIR`，并在 `target_link_libraries` 添加 `Sophus::Sophus`。

### 1.3 修改 YAML 后运行结果没有变化

根因：launch 读取 `install/` 中的已安装配置，不是直接读取 `src/`。

处理：重新 `colcon build`，然后在新终端重新 source；用 `ros2 pkg prefix fastlio2` 和 launch 输出确认实际路径。

### 1.4 `No module named rclpy`

根因：未加载 ROS/HRIC Python 环境。

处理：每个终端先 `source /home/nvidia/hric_tools/hric_env.sh`。

### 1.5 `rg: command not found` 导致 BrokenPipe

根因：机器人没有 ripgrep，管道下游提前退出导致 `ros2 param dump` 报 BrokenPipe。

处理：机器人上使用 `grep -Ei`；本地工作区搜索再用 `rg`。

## 2. 数据与 TF

### 2.1 FAST-LIO2 不接收雷达

根因：FAST-LIO2 订阅 `CustomMsg`，实机发布 `PointCloud2`。

处理：运行 `pc2_to_custom`，验证 `/fastlio2/livox_custom` 的发布者、频率和点时间偏移。不要修改厂家 Livox 驱动输出类型。

### 2.2 TF 重复、RViz 抖动或树断裂

根因：FAST-LIO2 默认 `lidar/body` 与 HRIC 现有 frame 冲突，或多个节点重复发布相同父子 TF。

处理：FAST-LIO2 固定使用 `fastlio_odom -> fastlio_body`；adapter 使用 `fastlio_odom -> my_nav_base_link`。用 `tf2_echo` 和 `view_frames` 检查唯一发布者。

### 2.3 把 `/fastlio2/world_cloud` 当成全局累计地图

根因：话题名称产生误解。

结论：它是当前帧转换到 world frame 的点云。若要保存累计地图，需要独立点云累积/下采样/保存逻辑，不能只抓一次该 topic。

### 2.4 ROS 2 图看不到节点或话题

检查：

```bash
echo "ROS_DOMAIN_ID=${ROS_DOMAIN_ID:-未设置}"
ros2 node list --no-daemon
ps -eo pid,args | grep '<process-pattern>'
```

常见原因：不同 domain、旧 daemon 缓存、节点已崩但图未刷新。仅在确认进程状态后执行：

```bash
ros2 daemon stop
ros2 daemon start
```

## 3. FAR 目标、路径与显示

### 3.1 RViz 点目标，FAR 没收到

先分清工具：

- Publish Point：`PointStamped`，应设 `/far_eval/goal_point`。
- 2D Goal Pose：`PoseStamped`，默认 `/goal_pose`，FAR 不直接订阅。

解决：运行 `far_waypoint_follower_trial.py` 进行 `/goal_pose -> /far_eval/goal_point` 转换，或直接发布 `PointStamped`。

### 3.2 某些区域无法用 Publish Point 取点

原因：Publish Point 依赖 RViz 可选中的已渲染表面；未扫描区域、空白处或视角遮挡处无法稳定落点。

处理：使用 2D Goal Pose 加转换脚本，或用明确坐标 `ros2 topic pub --once`。这只解决“目标输入”，不保证未知空间可通行。

### 3.3 `Publisher count: 1`，但 echo 超时

根因：端点存在，不代表当前目标触发了新消息。FAR 可能没有新路径、已经停止发布或 DDS 图是旧缓存。

处理：同时观察 `/far_eval/goal_point`、`/far_eval/way_point` 时间戳、FAR 终端日志、`/viz_path_topic` 和真实进程。

### 3.4 MarkerArray 取消勾选后“路线消失”

`/viz_graph_topic` 和 `/viz_path_topic` 类型不同：

- V-Graph：`MarkerArray`
- 路径：`Marker`

应分别添加两个 display。取消一个不会影响节点，但可能正好隐藏所需内容。

### 3.5 远目标等待超时或被范围拒绝

旧脚本把“最终目标距离”和“局部航点/路线范围”混在一起，5 m 外目标会提前拒绝。当前主脚本已分开：

- `--max-goal-distance`
- `--max-route-distance`
- `--planner-timeout`

实验上限已允许设到 20 m，但 FAR 的 `local_planner_range=5.0` 仍是规划器内部局部范围。把脚本限制改大不会自动增强 FAR 的地图覆盖和避障能力。

### 3.6 FAR 路径只有起点和终点，穿过障碍

实测 `/viz_path_topic` 曾只有两点，而且 `/far_eval/way_point` 持续等于全局目标。说明 FAR 在当前地形/障碍输入下认为可以直达，并没有产生绕行中间点。

诊断命令：

```bash
timeout 10 ros2 topic echo /far_eval/way_point --field point
timeout 10 ros2 topic echo /viz_path_topic --once --field points
timeout 10 ros2 topic echo /FAR_obs_debug --once --field width
```

解决方向：

1. 修正 terrain/FAR 对低矮障碍的识别。
2. 在控制层使用独立 costmap + 局部 A*，不能仅依赖 FAR 直线。
3. 路径线穿障碍时禁止运动，不能把“有蓝线”当作安全证明。

## 4. 低矮障碍漏检

### 4.1 已确认现象

- 柜体高度低于雷达，但原始点云中可见。
- FAR 仍输出直连路径。
- `/FAR_obs_debug` 有大量点，只能证明 topic 有数据，不能证明目标柜体被分类为障碍。
- costmap 中某些障碍可见，但红框低矮区域仍可能未被标记。

### 4.2 当前最强诊断假设

局部 voxel costmap 当前观测参数包括：

```text
origin_z: 0.0
z_resolution: 0.125
z_voxels: 16
source min_obstacle_height: 0.08
source max_obstacle_height: 1.8
obstacle_min_range: 0.3
```

而 FAST-LIO2/机器人附近地面 z 曾约为 `-0.69 m`。如果 body cloud 或变换后的障碍点仍落在负 z，`origin_z=0.0` 和 `min_obstacle_height=0.08` 会过滤地面以上但仍低于 z=0 的低矮物体。

这是**诊断假设，尚未完成对照实验**。推荐验证：

1. 对原始 `/fastlio2/body_cloud`、`/fastlio2/world_cloud`、terrain map、`/FAR_obs_debug` 做同一 ROI 的 z 分布统计。
2. 记录一包固定场景数据。
3. 只改变一组高度参数做 A/B 回放。
4. 尝试把 voxel `origin_z` 下移，例如 `-1.0`；把 source 的 `min_obstacle_height` 下调到略高于地面噪声，例如先试 `-0.55`，再依据实测分布调整。
5. 确保不会把整片地面标成致命障碍。

此外，`obstacle_min_range=0.3` 和 footprint clearing 会在机器人近处形成清空区，这是预期机制，也可能解释紧贴本体的小障碍缺口。

### 4.3 FAR terrain 参数

当前 terrain 高度窗口很宽，但参数尚未按雷达安装高度和本体尺寸标定。需要对 `minRelZ/maxRelZ/lowerBoundZ/upperBoundZ/vehicleHeight/robot_dim` 做基于实测点云的配置，而不是只凭 RViz 颜色调参。

## 5. 无图运动与运控

### 5.1 HRIC 原生 StartNav 无响应

HRIC 原生导航依赖地图加载、`/hric/loc/pose`、全局/局部规划和 tracker。只启动接口壳、没有地图定位输出时，`StartNav` 不会形成完整链路。

本项目当前目标是无图导航，因此采用 `/my_nav/odom + FAR + cmd_vel` 的实验链路，而不是把 FAST-LIO 坐标硬映射成 HRIC `map` 目标。

### 5.2 低速只晃动、不走或不转

现场记录：

- `0.05 m/s`、`0.1 rad/s` 常无法驱动。
- `0.4 m/s` 线速度能够行走。
- `0.4～0.5 rad/s` 原地角速度能产生约 10° 转动；更低时只轻微晃动。

这说明平台存在命令死区或步态门槛。当前主脚本默认实验参数提高到了线速度约 0.4 m/s、角速度上限 0.6 rad/s。仍应在空旷区分段测试，不应把该经验值当成所有地面/电量/步态下的绝对常数。

### 5.3 转弯半径太大

曲率关系：

```text
R = v / |w|
```

当 `v=0.4 m/s`、目标半径 `R=0.8 m` 时，需要约 `|w|=0.5 rad/s`。若角速度上限只有 `0.1～0.3 rad/s`，实际半径会变为 1.33～4 m，看起来几乎直行。

当前参数：

```text
--max-linear-speed 0.4
--turn-linear-speed 0.4
--arc-linear-speed 0.4
--max-angular-speed 0.6
--turn-radius 0.8
```

### 5.4 GO 后提示没有新 waypoint

根因：人工输入 `GO` 时 Python `input()` 阻塞回调，或者 FAR 在确认期间没有重新发布航点。

当前脚本处理：

- GO 前缓存并校验航点。
- GO 后刷新里程计与安全反馈。
- 允许短时间使用最近的已验证航点作为 bootstrap。
- 进入运动后再要求航点流持续更新。

如果仍发生，检查 FAR 是否持续发布以及目标是否被 FAR 判定已经到达。

### 5.5 `cmd_vel_status` 非零但机器人没有移动

`cmd_vel_status` 只证明运控链路接收了命令，不证明机器人真实完成动作。实际运动判定必须结合：

- `/my_nav/odom` 的净位移和航向变化
- `/hric/robot/walk_speed`
- 现场观察

本轮转向测试中 `walk_speed` 可能仍为 0，但里程计显示约 10° 变化；因此不能只依赖单一反馈。

### 5.6 多个速度发布者冲突

曾同时出现：

- `joystick_bridge_node`
- `hric_path_tracker`
- 自定义跟踪器准备发布

自定义脚本会拒绝启动。正确处理：停止 tracker 的 launch 和实际子节点；杀父进程后还要检查子进程是否成为 PPID 1。DDS 端点可能短暂残留，确认进程已退出后可重启 ROS daemon。

不要绕过端点保护让多个控制器同时写 `/hric/robot/cmd_vel`。

## 6. 局部 costmap 与 A*

### 6.1 costmap 能停车，但 FAR 不给新点

原因：FAR 不订阅 `/my_nav/costmap`。独立 costmap 报障碍不会促使 FAR 自动更新中间航点。

正确架构是：

- FAR 给较远的全局/局部目标。
- costmap + 本地 A* 生成近场可执行路径。
- 跟踪器追踪 A* 的 lookahead 点。
- 路径失效时重规划，而不是只停下来等 FAR 改点。

### 6.2 预检有 A*，执行仍停车

这是当前尚未闭环的问题。现象说明预检路径搜索可用，但运行时碰撞门控仍可能优先检查原始 FAR 直达方向，或局部路径没有稳定接管控制目标。

下一步应通过日志同时打印：当前控制目标来源（FAR/A*）、A* 路径长度、lookahead 栅格、扫掠检查对象，并在 bag 回放中复现。未完成该验证前，不得宣称避障已经完成。

## 7. bag 与可复现诊断

已使用如下组合记录柜体场景，约 50 秒产生 5 GiB：

```bash
ros2 bag record --storage sqlite3 \
  -o ~/fastlio2_maps/diagnostics/cabinet_test \
  --topics \
  /fastlio2/world_cloud \
  /far_eval/terrain_map \
  /far_eval/terrain_map_ext \
  /FAR_obs_debug \
  /my_nav/odom \
  /far_eval/goal_point \
  /far_eval/way_point \
  /viz_path_topic
```

后续应增加 `/fastlio2/body_cloud`、`/my_nav/costmap`、`/my_nav/voxel_grid`、`/my_nav/local_avoid_path` 和速度反馈。高频点云体积很大，建议缩短时长或按需降频。
