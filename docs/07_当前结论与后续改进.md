# 当前结论与后续改进

## 1. 已达成的阶段结论

本项目已经证明以下路线可行：

```text
MID360 -> PointCloud2/IMU -> FAST-LIO2 -> FAR 航点
       -> 自定义无图跟踪器 -> HRIC cmd_vel -> 天工机器人运动
```

这不是概念验证停留在 RViz：现场已确认机器人能够根据该链路发出的命令直行和转向。曾经“只有直线能走、侧向目标不动”的主要原因包含平台速度死区、角速度上限过低导致曲率不足，以及速度发布者冲突，而不只是 FAR 坐标错误。

## 2. 不能做出的结论

目前不能声称：

- FAR 已可靠识别所有障碍。
- FAR 自身会根据 `/my_nav/costmap` 重新生成中间航点。
- 低矮柜体避障已经解决。
- 局部 A* 已在实机完成连续绕障。
- 20 m 目标可直接安全执行。
- 当前雷达外参、机器人 footprint 和 terrain 高度参数已经标定。

## 3. 下一阶段优先级

### P0：补齐源码快照

先在机器人执行 `collect_robot_sources.sh`，把当前实际能运行的 converter、adapter、terrain、FAR 和 `/home/nvidia/hric_tools` 脚本收回。没有这一步，后续修改容易基于错误版本。

### P1：验证低矮障碍在哪一级丢失

对同一柜体 ROI 依次统计：

1. `/fastlio2/body_cloud`
2. `/fastlio2/world_cloud`
3. `/far_eval/terrain_map`
4. `/far_eval/terrain_map_ext`
5. `/FAR_obs_debug`
6. `/my_nav/voxel_grid`
7. `/my_nav/costmap`

每一级记录点数、z 最小/最大/分位数和二维占据结果。不要先猜算法，先定位数据在哪一级消失。

### P2：修正 costmap 高度窗口

基于 ROI 结果对 `origin_z`、source 的 `min_obstacle_height/max_obstacle_height` 做单变量 A/B 测试。当前优先验证“负 z 低矮物体被过滤”的假设，同时防止地面整体变成障碍。

### P3：让局部 A* 真正接管控制目标

给主 follower 增加明确状态输出：

```text
CONTROL_TARGET=FAR_WAYPOINT
CONTROL_TARGET=LOCAL_ASTAR_LOOKAHEAD
BLOCKED_BY_COSTMAP
LOCAL_REPLAN_FAILED
```

执行时的碰撞检查应针对当前局部路径段，而不是每次都用原始 FAR 直达线。局部路径失效应重新规划；超过阻塞超时才停车。

### P4：标定本体和速度模型

- 实测机器人最大横截面和动态摆动余量，替换临时 `0.45 m` 足迹半径。
- 实测不同地面/电量下的最小可执行线速度和角速度。
- 用 `R=v/|w|` 验证 0.8 m 目标转弯半径是否真实成立。
- 校验 FAST-LIO body、实际机器人朝向和雷达安装外参。

### P5：工程化速度仲裁

当前靠停掉 `hric_path_tracker` 保证单一发布者，只适合实验。生产化应加入明确 mux/lease/watchdog：遥控急停优先，自主控制持有短租约，超时自动零速，状态机切换可审计。

## 4. 推荐的验收阶梯

1. 静止传感器 10 分钟：TF、里程计、点云无异常跳变。
2. 只读目标：前、左、右各 3 个点，方向计算正确。
3. 空旷单航点：0.5 m、1 m、2 m，记录位移和转角。
4. 空旷组合路线：直线、左转、右转、S 弯。
5. 人工障碍：高墙板，再测低柜体；先预检不运动。
6. 局部 A* 可视化：确认路径不穿膨胀障碍。
7. 0.5 m 最大移动上限的绕障试验。
8. 2 m 分段绕障试验。
9. 5～20 m 远目标，保持分段移动和实时重规划。

每一级通过后再进入下一级，保留 bag、参数 dump、脚本哈希和终端日志。

## 6. 本归档的用途

这套分册用于：

- 新机器从零复现 FAST-LIO2 + FAR。
- 下次重启时恢复 A～G 终端。
- 快速判断问题属于驱动、消息转换、TF、terrain、FAR、costmap、跟踪器还是运控。
- 对照机器人端当前源码，避免丢失已调通的本地修改。
- 为后续低矮障碍识别、局部规划接管和工程化控制仲裁提供基线。
